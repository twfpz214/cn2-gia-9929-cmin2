## 三网回程优化到底在优化哪一段

数据中心到你家宽带之间有两条路。去程是你访问服务器，走国内运营商的国际出口，这段通常还好走；回程是服务器把数据传回来，走的是机房上游到国内的通道，国际拥塞主要发生在这里。晚高峰掉速、视频卡顿、SSH 输入延迟，绝大多数出在回程。

所以"三网回程优化"实际做的事，是给电信、联通、移动各配一条相对通畅的回国通道，别让三家数据包一起挤在公网国际出口上。这个说法各家都在用，具体到线路编号，主流是三条：

- **电信 CN2 GIA（AS4807）**：电信精品承载网里等级最高的一档，比普通 CN2 GT（AS4134）贵，晚高峰表现稳定。GIA 是 Global Internet Access 的缩写。
- **联通 AS9929（CUII）**：联通精品网，业内常把它和 CN2 GIA 放在同一档讨论。性价比是它的优势。
- **移动 CMIN2（AS58807）**：移动的精品回程，带宽给得比较大方，对移动用户改善明显。

不同来源对线路编号的标注有出入。有测评把联通回程写作 AS10099 + AS4837、移动回程写作 AS58453（CMI）+ AS9808，这套编号描述的是国际段与国内段的分段路径，和上面三条并不矛盾，只是统计口径不同。看路由记录时按实际跳数判断，别把编号当成结论。

## 三条精品线路，三种常见做法

同样是"三网优化"，商家给的方案可以差出很多钱。

**三网分线**：电信走 CN2 GIA、联通走 AS9929、移动走 CMIN2，三家各走各的。理论上对三类用户都是最优，成本也最高，套餐价格通常最贵。

**回程统一走 9929**：三网回程全部汇到 AS9929 精品网。不如分线那样各走各的，但 9929 本身质量稳定，价格能压下来一截，是性价比路线。

**智能路由**：典型做法是电信回程小包走 CN2 GIA、大包走 AS4134（163）。小包是 HTTP 请求、SSH 输入、控制信令，拿低延迟；大包是文件传输和视频流，拿大吞吐。这种策略对建站用户比较友好，等于把两种线路的长处拆开用。

选哪种，取决于你的用户结构和业务形态。用户以电信为主、对延迟敏感，分线的钱花得值；三类用户都有、预算有限，统一 9929 更务实；主要是网页和接口访问，智能路由的性价比通常最好。

## 怎么验证商家说的三网回程优化

这一节是全文最该记住的部分。前排文章大多止步于"晚高峰实测很稳"，但"稳"没有口径就无法复核。下面这套方法可以直接拿去用。

**去程和回程分开测。** 从三家运营商的探针访问服务器的业务端口，记录 DNS 解析、TCP 建连、TLS 握手、首字节、完整响应和下载速率。回程则要从服务器侧向受控探针发起探测，或者要求商家提供各运营商、各目标区域的回程路由说明。只凭自己 ping 一下服务器，测到的是去程。

**用 TCP 443，不要只用 ICMP Ping。** 部分网络会对 ICMP 限速、降级或延迟处理，Ping 好看不代表 HTTPS 业务好看。Linux 下可以这样拆解：


traceroute -T -p 443 example.com



curl -o /dev/null -sS --connect-timeout 5 --max-time 20 \
  -w 'dns=%{time_namelookup}\nconnect=%{time_connect}\ntls=%{time_appconnect}\nttfb=%{time_starttransfer}\ntotal=%{time_total}\nspeed=%{speed_download}\n' \
  https://example.com/health


`/health` 换成一个处理逻辑简单、返回内容固定的地址，别用带数据库查询的页面，否则应用耗时会把线路差异盖掉。一条示例记录长这样：


dns=0.012  connect=0.031  tls=0.068  ttfb=0.142  total=0.210  speed=8420000


单位是秒，意思是 DNS 约 12ms、TCP 建连约 31ms、TLS 约 68ms、首字节约 142ms、整个请求约 210ms。单次记录不能当结论，要连续采样。

**看 p95 和 p99，不看平均值。** 平均值会把晚高峰的抖动和少量严重超时抹平。p50 是大多数请求的常见水平，p95 反映较差的那部分请求，p99 是尾部延迟，对交易、接口、实时交互最有参考价值。

**故障归因按段拆。** 只有 TCP 建连变慢，可能是路径问题；建连正常但首字节慢，去查服务器处理、数据库或应用线程；首字节正常但完整响应慢，看回程带宽、并发数和响应体大小。

**中间跳丢包别当业务丢包。** 某一跳显示丢包，后续节点和目标都正常，大概率是那个节点限制了探测报文。以最终目标的端到端丢包和业务请求失败率为准。

**测试探针要接近真实用户。** 云主机之间互测只能反映云厂商之间的路径，代替不了家庭宽带、企业网络和移动网络。移动端占比高的业务只测固定宽带，结果会偏乐观。单个城市的三网结果也不能当全国结论，测试报告至少要留下地区、接入运营商、网络类型、测试时间与时长、服务器 IP、协议端口、IPv4 还是 IPv6、去程回程路径。

**IPv4 和 IPv6 分开测。** 部分用户会优先走 AAAA 记录，IPv6 的路径质量和 IPv4 可能完全不同，混在一起测会掩盖其中一条的问题。

还有一条经验：至少连续观察 24 小时，覆盖一个完整的晚高峰。只看白天的几分钟，等于没测。

## 端口带宽与流量口径

"300Mbps 带宽"描述的是端口上限，不是你在任何时段、任何运营商下都能拿到的单连接速度。欧洲线路 RTT 通常在 180ms 以上，长延迟下单连接的 TCP 吞吐受窗口大小限制，多线程并发才可能跑满端口。看到测速只有几十 Mbps 就判断线路差，这个结论下得太早。

容量要按业务量倒推。每天外发 200GB，按十进制 GB 计算，平均速率是 `200 × 8 × 1000 ÷ 86400 ≈ 18.52 Mbps`；如果高峰是平均值的 5 倍，粗略峰值约 92.6 Mbps。这是容量估算，不代表该直接买 100Mbps 端口，因为并发数、响应大小和计费规则还要单独看。

下单前值得问清楚的几件事：带宽是独享、共享还是峰值资源；上下行是否对称；按端口、按流量还是按 95 分位计费；三网是共享一个总带宽还是各运营商分别有容量；有没有连接数或突发速率限制；超额之后怎么计费和限速。AkkoCloud 的套餐流量按双向计算，这一条会直接影响你的实际可用量，跑下载或同步业务时要按一半折算。
